## 目标

将游戏中心、东方农场、今晚餐桌及现有世界杯模块提升到统一的精品休闲游戏完成度。画面要有空间、光照和材质层次；操作要直接、稳定且有反馈；玩家要知道现在能做什么、下一步为什么值得做。

“无可挑剔”作为验收目标，不作为未经实测的承诺。每一部分交付要提供实际运行画面及交互证据，设备或网络限制要说明。

## 已核实的现状

- 仓库 `D:/easternmarket.ca/eastern-farm`，检查时分支 `dinner-tonight`，HEAD `4f5905a`，工作区干净。分支已有餐桌改动，实施前须核对远端分支及生产差异。
- 首页有两张图片卡片，缺少统一的继续游玩及各游戏返回入口。
- 农场已有等距世界、种收动画、音效、七款程序化配乐、订单、建造、邻居和存档。升级应以这些系统为基础。
- 390px 手机线上实测：农场金币和积分按钮高约 23px，缩放、语言和音乐按钮为 36px；需要扩大触控范围并重新安排空间。
- 餐桌初次打开没有可见操作说明和进度，菜盘的 `role=button` 元素不可用 Tab 聚焦，页面没有返回链接。已有拖拽与甩动旋转应保留。
- 世界杯页面已显示赛事结束，但部分历史赛程仍显示“未开始”“待更新”，需要区分赛事归档与资料缺失。保留原始赛果，不猜测比分。
- 本机 HTTP 预览已恢复为 `http://127.0.0.1:8037/`，已确认首页和餐桌真实加载。localhost 下餐桌接口有预期的 CORS 限制，使用现有本地菜单兜底；改后仍需浏览器交互验收。

## 整体设计方向（建议，由实施方提出）

保留品牌深绿、奶油白、暖金侧光和已有油画资源。画面主体优先，界面退后；避免把“豪华”做成黑金赌场风、密集徽章或满屏发光按钮。

统一按钮、标题、数值、面板、焦点态和过渡语言，各游戏保留自身场景：农场是温暖的经营世界；餐桌是有陶瓷和食物质感的互动餐桌；世界杯是清楚易读的赛事归档。

字体沿用已有可靠字体与系统回退。正文保持清晰，数值使用等宽数字。保留农场“小薇”字体“回”字补丁，所有标题与长英文都要在手机上验证。

## 1. 游戏中心

- 重做首屏构图：品牌、清楚的游戏中心标题、主游戏场景和直接开始按钮。手机上合理展示各游戏，不靠一张超高卡片占满整个首屏。
- 两款常驻游戏提供中文及英文名称、玩法说明和明确入口。世界杯放入季节活动或赛事回顾区，明确已结束。
- 加入本机“继续游玩”入口，只记录最近访问的游戏路由，不解析或改写余额、云存档、会员身份。
- 每款游戏有随时可找到的返回游戏中心入口。浏览器后退不被劫持。
- 选择页图片预留尺寸和加载状态；本地封面优先，图片失败不留下空白交互区。

## 2. 东方农场

- 重新整理顶部身份与货币区、今日状态、底部快捷入口、地图工具区；重点是农场画面与常用动作，次要工具进入清楚的菜单或工具组。
- 交互目标至少 44×44 CSS px，手机刘海与底部安全区内不遮挡。主操作、货币和经验进度层级清楚，数值变化不引起跳动。
- 优化现有任务/收获状态与新手引导：每次突出一个当前可执行动作，新玩家完成种植、收获、按订单交货的闭环。保留帮助入口，避免连续自动弹窗。
- 保留既有种收、建造、走路和驾驶动作；按压、选中、执行中、完成、失败有不同反馈。审查拖地图、点击物件、长按建造和双指缩放的冲突，以及 pointercancel 后的状态清理。
- 优化地块选中和成熟提示、场景阴影与界面材质的一致性；世界背景继续程序化绘制，不用整幅背景图取代世界坐标。
- 音乐和音效开关状态清楚；不新增强制出声。弱性能设备减少装饰效果，减少动态效果偏好生效。
- 保持现有作物时长、价格、奖励、订单和存档结构。新的作物、建筑、经济曲线及额外奖励不在本次默认实施范围。

## 3. 今晚餐桌

- 初始画面加入游戏标题、一个完整的操作提示和四菜一汤的可视进度。首屏内同时看见餐桌、当前菜和主要操作。
- 重新打磨桌面、碗碟、食物图片、接触阴影及落盘动画；缩小 Logo 与空白对内容空间的占用。食物图失败时显示对应菜名和明确替代视觉。
- 保留拖拽摆盘和甩动旋转；增加等价的点击/键盘摆放路径。当前菜、可落位置与落下结果清楚；拖拽取消、滑出窗口及快速连点不会重复放菜。
- 四菜一汤全部放好后，清楚显示完成状态、菜单、分享和重新摆桌入口。重新开始只重置本轮餐桌，仍使用已加载的菜单，不增加接口请求。
- 返回游戏中心始终可见。分享成功、取消、不支持或失败分别处理；复制失败时提供可选择的菜单文本。
- 菜单继续使用现有公开接口和本地兜底；超时或失败有可重试状态。没有数据不伪装成空桌已成功加载。
- 不接入新的优惠券、积分、抽奖或采购写入。

## 4. 世界杯 / 季节活动模块

- 加入统一返回入口、字体、按钮和手机布局，保留赛事模块辨识度。
- 根据本地时间及真实数据区分赛前、进行中、已结束、赛事归档和资料待补；归档时不将缺少终场数据的旧比赛标成未来“未开始”。
- 保留赛程筛选、积分榜、对阵图及我的奖品。小屏对阵图提供明确横向浏览提示，不裁掉队名或操作。
- 保留官方结果字段、积分排序、竞猜和奖品结算流程；不补猜赛果、不发奖、不触发后台写入、不重新开启已结束的竞猜。

## 工程范围

主要预计涉及首页、三款入口页面、各自 CSS/JS、共享的游戏中心导航/样式、Service Worker 的相关资源清单，以及 `scripts/verify/` 内必要的回归验证。

新增共享层只负责视觉、导航、可访问性和本机最近访问记录，不接管农场经济或云同步。继续原生静态应用，不迁移框架、不增加运行时包依赖。

具体文件拆分、动效曲线、断点和素材取舍由实施方在既有规则内决定；新图片若确有必要，再按项目出图规则生成与验收，不以无版权来源的游戏素材占位。

## 验收标准

- 在 360、390、768、1440 CSS px 检查整体构图及核心状态；小屏无页面级横向溢出，赛事对阵图的有意横向滚动除外。
- 所有常用按钮至少 44×44 CSS px；键盘能访问主要动作；焦点、禁用、加载和失败状态有明显区别。
- 每款游戏提供可发现的返回入口。首次到餐桌能理解摆盘方法；完成后能分享、重新摆桌和返回。
- 农场完成种植、收获、交订单、商店、任务、建造、菜单，以及刷新恢复；已有存档内容保持，云同步代码路径不被视觉层绕过。
- 手机测试长按/拖动、轻触、双指缩放、取消手势、横竖屏和页面失焦；动画不导致双触发。
- 验证中英文、长菜名、缺图、无网/慢网、分享失败和 reduced-motion。
- 正常路径没有未捕获脚本异常。测试拦截游戏埋点，不向真实经营统计灌入测试数据。
- 运行现有语法、启动、入口及相关交互契约检查；保留 Service Worker 更新回归，确认旧 PWA 能拿到新版本。
- 性能以相同设备及场景做前后比较，记录加载和帧时间。农场不得比升级前更卡；60fps 是优化目标，不能在未测真实设备前宣称达成。
- 提供桌面/手机改后截图与交互记录。iPhone 17 真机验证若无法在当前环境进行，明确留下该项，不用模拟器结果冒充。

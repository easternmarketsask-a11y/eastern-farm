# 今晚吃什么 · 设计（2026-10-29）

## 一句话

客人用一分钟决定今晚这道家常菜该下哪些食材。做对了，清单里指定的那样，下次在东方超市结账减 $1。全对再参加本周六的菜篮抽奖。

农场继续留给愿意天天种菜的人。这一页不进农场的画布，也不等 Firebase 才开得了火。

## 客人看到的三步

1. **开火前。** 萨省日历上的今天一道菜，中文名、英文名、一句做法。周日店休，当天显示明天的菜，并写明「今天周日，店休。这是明天的菜，先把清单备好。」
2. **掌勺。** 八道食材一道一道来。下锅，或留下。九十秒，超时没点到的算错过。油还热着的倒计时平时不吵，最后十五秒才变色。点错会说完整的一句：「这味不用下锅。」或「这味要下锅。」
3. **出锅。** 四样真要买的，写在一张纸上。减 $1 的那样盖一个红章。可以再练一锅，再练的成绩不换掉今天第一锅的券。也可以把清单发给家里人。

## 星和钱

八道里：

| 点对 | 星 | 减 $1 | 周六菜篮 |
|---|---|---|---|
| 8 | 3 | 有 | 有 |
| 6 或 7 | 2 | 有 | 无 |
| 4 或 5 | 1 | 无 | 无 |
| 3 及以下 | 0 | 无 | 无 |

没到减 $1 的，清单照样留下。

减 $1 的规矩：

- 减的是这道菜指定的那样，必须和它出现在同一张小票上。
- 每个会员七天一张。
- 全店每个萨省日最多 20 张。发完了，这份资格记到第二天优先领，客人不用再打一锅才排得上。
- 还不是会员的人可以玩、可以看清单。券要记到店里的会员上，用店里登记的手机号确认「是你吗」。

周六菜篮每周一份，东西由店主定，建议 $15 以内。这一版只把全对的人记进当周周六的名单，不开自动抽奖。

## 菜单

七道菜写在 `data/dinner-menu.json`。改这个文件就换菜，不用改页面。每道 4 样下锅、4 样干扰，减 $1 的那样必须在下锅的四样里。顺序由当天的 seed 洗牌；同一 seed 永远同一顺序，服务器用这个核对客户端没有换牌。

从 2026-01-01 起，按萨省日期轮换。周日和周一看同一道（周一那道）。领取时送出的日期是这道菜的日期：平日就是今天，周日是明天。服务器只接受今天、昨天，以及周日时的明天。

## 页面

`src/dinner.html`。宽屏收成一条案板，给手机单手用。

- 开火前就能玩，不加载 Firebase。
- 登录脚本只在点「把减 $1 记到会员」时才拉。
- 不注册农场的 Service Worker 预缓存。新文件走浏览器自己的网络。
- 食材是同一套填色的画，不用 emoji。
- 中文菜名用宋体，英文用 Palatino 斜体，按钮用苹方。

## 领券

客户端把 `{ date, dishId, seed, picks }` 交给云函数 `dinnerClaim`（源码在 `dinner/dinnerClaim.ts`，部署在 `eastern-market-members`）。函数自己重算星级，不信浏览器报的分数。

函数还没部署时，页面照实说：成绩记下了，券码要等店里开通核销后才会显示，清单现在就能用。不发一张收银员无法核对的假码。

核销沿用「报码、查一次、作废」的方式。现有世界杯核销页查的是另一套券，晚餐券要等 `dinnerClaim` 上线后另接。在那之前，不要让收银按截图减 $1。

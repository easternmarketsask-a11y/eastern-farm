# 东方超市订单制 · 设计（2026-08-22）

## 一句话

取消「无限收购」，卖菜改成**只能按东方超市的订单供货**；订单不定期到达、有接单上限、
提前预告，并优先反映真店的特价与应季。

## 背景与问题

Chris（2026-08-22）：「如果东方超市不再无限收购，怎样使玩家仍然有生产动力。
改变销售模式，只能根据东方超市的订单供货，不再是自己想卖什么就能卖。」

现在有三条卖菜路：

| 渠道 | 实现 | 现状 |
|---|---|---|
| 谷仓「卖给东方超市」 | `state.deliverWarehouse` / `warehouse.deliver()` | **无限收购**，基础价（应季 +15%、每日首卖 +20%）|
| 菜摊路人 | `stall.js` | 1–3 棵，1.35–1.6×，间隔 ≥25 分钟 |
| 订单板 | `orders.js` | 3 个常驻槽，1.5×，**免费换单 + 交付后立刻补位** |

⚠️ **关键观察**：订单板目前**也是无限的**（能免费换单、交完立刻补位）。
只把谷仓关掉，玩家照样想卖什么卖什么，只是多点几下。
**「不定期」必须落在订单本身的稀缺性上**，否则这次改动等于没改。

⚠️ **本设计要对抗的失败态**：稀缺性带来「种出来的菜没人订 → 仓库塞满 → 卖不掉 →
卡死 → 弃坑」。Hay Day / Stardew / Township 都没有真正取消过兜底出口，原因就在这。
下面的「三道阀」和「预告板」就是为这件事存在的。

## 已定决策（Chris 2026-08-22）

1. 谷仓大宗收购**取消**；菜摊路人**保留**当零钱与泄压阀。
2. 订单**随机时刻**到达 + 有提醒。
3. 订单内容**跟真店挂钩**：真特价 / 应季优先上单。
4. 保留「每日基础补货」（防卡死地板）；同时接 3 单；有效期 3–8 小时。
5. NPC「小东」改名「**东超**」。

## 一、三层需求

### ① 每日基础补货（地板，量小）

每天开服时贴出 2–3 样「店里天天要」的基础菜，**各自限量**，价格 1.0×（仍吃应季 +15%）。

- 作用：收入下限、任何时候都有活干、新手不会把自己玩死。
- **不是无限收购**：有量的上限，卖完就没了；想多赚必须等不定期单。
- 限量口径：单样上限 = 「玩家当前地块数 × 该作物一天可收次数 × 单次产量」× `STAPLE_RATIO`，
  也就是「够卖但不够躺」。**`STAPLE_RATIO` 的值由第五节的模拟标定，先以 0.6 起步** ——
  它直接决定新经济是紧还是松，不许拍脑袋定死。

### ② 不定期订单（主收入）

- 一天 **3–6 波**，两波间隔 **40–150 分钟随机**（不是固定档期）。
- 每单要 **1–3 种**菜，中等量；价格 **1.5–2.2×**（多品种、大数量的单溢价更高）。
- 有效期 **3–8 小时**（够错过一波，不至于全错过）。
- 板上最多同时挂 **5 单**，玩家**只能接 3 单**。

🔒 **接单容量就是「不能想卖什么就卖什么」的另一半**：不是限制你卖，是逼你选。

「接单」的确切语义（这几条不写死就会各做各的）：

- **必须先接单才能交付**。没接的单只能看 —— 否则接单上限形同虚设。
- 接了的单**有效期照常走，不冻结、不延长**。接单是占位，不是保险。
- 可以**主动放弃**已接的单腾位置，**无任何惩罚**（不扣钱、不冷却）。
- **每日基础补货不占接单位**，它是地板，永远可交付。
- **大单占板位也占接单位**，跟普通不定期单一样——「要不要为这张大单腾两个位置」
  本身就是有意思的取舍。

🔒 **过期不惩罚**：订单（已接的和没接的一样）只是消失，
**不扣钱、不掉声望、不影响后续出单节奏**。
妈妈玩家会离线一整天，惩罚性倒计时会直接赶走人（与 `orders.js` 现有的
「No timers / no pressure (cozy)」原则一致）。

### ③ 大单（少见，高回报）

周末 / 节日 / 真店大促时出现。要 3–5 种菜、数量大，溢价 ≥2.5×，并给超市积分。

🔒 超市积分**继续受现有 `ORDER_EP_DAILY_CAP = 4` 约束**，不因为大单破例
（EP 是真实会员积分，是真金；见 `orders.js` 的 currency discipline 段）。

## 二、备货预告板（本设计的灵魂）

订单板顶部常驻「**东超下周想要什么**」：提前 **3–7 天**公布将要出现的菜。

没有预告，随机订单是**惩罚**（种了没人要）；有了预告，它变成**备货游戏** ——
而「备货」正是「根据东方超市的订单供货」的实质。真实超市本来就是提前排促销档期的，
语义完全吻合。

预告来源优先级：真店特价排期（二期）> 应季表（`crops.isInSeason`）> 玩家已解锁作物随机。

## 三、真店挂钩（二期）

StockWise 新增 `GET /api/public/farm-demand`（公开、只读、可缓存）：
返回本周特价（`is_on_sale`）+ 应季商品，映射到 `crops.json` 的作物 id。

- 命中的作物在出单/预告里权重 **×3**，卡片标「本周店里也在特价」。
- 游戏侧已有同域公开端点的调用先例（`/api/public/game-track`、`/api/public/farm-feedback`、
  `/api/public/member-auth/whoami`），沿用同一套 fetch 姿势。

🔒 **必须优雅降级**：拉不到 / 超时 / 后端 500 → 退回纯游戏内随机，**不能没订单**。
boot 路径的任何 await 都要有硬超时（`main.js` 的 `withTimeout` 教训，见项目 memory）。

## 四、防卡死三道阀

1. **菜摊路人** —— 保留不动（≤3 棵 / ≥25 分钟，太慢太少，抢不了订单的饭）。
2. **每日基础补货** —— 收入地板。
3. **厨房加工**（已有 `kitchen.js`）—— 卖不掉的原料做成菜，菜有独立需求。

## 五、经济标定（不能拍脑袋）

- 改前：收入 ≈ 产量 × 基础价（产多少卖多少）
- 改后：收入 ≈ **min(产量, 需求) × 溢价**

🔒 **不变量：同等活跃度下，日收入不得低于旧模式。** 否则玩家体感是「被砍了一刀」。

标定办法：写一个纯函数的经济模拟（不依赖浏览器），输入
「地块数 / 每日登录次数 / 作物组合」，输出新旧两套模式下的日收入曲线，
反推溢价与单量系数。这个模拟本身进测试，防止以后调参调崩。

## 六、必须处理的连带

### 6.1 `totalDeliveries` 接管（最容易漏）

`totalDeliveries` 目前**只有** `state.deliverWarehouse` 会加（`state.js:1184`），
订单交付不加。删掉大宗卖货 = 这个计数永久冻结，连带全部静默失效：

| 消费方 | 坏掉的表现 |
|---|---|
| `life-story.js` | `deliver_first`、`deliver 25/100` 章节永不触发 |
| `neighbors.js` / `firebase-game-sync.js` | 排行榜、邻居卡片的「交付数」永远 0 |
| `daily.js:167` | `isNewbie`（<3 单）永远判新手 |
| `analytics.js` | 漏斗事件 `sell_first` 永不上报 |
| `spotlight.js` | 以 `totalDeliveries++` 为状态变化信号 |
| `ai-neighbors.js` | AI 邻居用它推算数值 |

→ **订单交付必须接管 `totalDeliveries`**。语义上也更对：它本来的注释就是
「warehouse→Eastern Market deliveries」，订单交付正是这件事。

### 6.2 大宗卖货的入口与残留

- 谷仓面板的「🏪 卖给东方超市」按钮移除。
- 仓库满弹窗的两个选择从「卖掉 / 扩仓」改为「**看看东超要什么** / 扩仓」。
- `state.deliverWarehouse` 与 `warehouse.deliver()` 失去全部入口 → **删掉**，
  不留死代码（项目铁律：两处画同一种东西先合并；死代码同理）。
- `orders.reservedNeeds`（防止一键卖货把攒给订单的菜卖掉）在大宗卖货消失后，
  只剩菜摊会动库存。菜摊单次 ≤3 棵，**维持现状不加预留约束**；库存不够自然不成交。
- `coach.js` 的 `first_sell` 文案「售出可得农场币。每日首单 +20%」要改（首卖 +20% 随大宗一起没了）。

### 6.3 「小东」→「东超」（58 处 / 20 个文件）

`src/css/style.css`、`src/index.html`、`src/js/{coach,daily,farm,farmer,guide,kitchen,
life-story,main,orders,rewards,spotlight,state,storekeeper,tasks,warehouse}.js`、
`data/{achievements,chapters,recipes,tasks}.json`。

- 仅中文串与注释；英文侧本来就是 "Orders" / "Kitchen" / "the storekeeper"，不动。
- 「小东订单」→「东超订单」、「小东厨房」→「东超厨房」。
- ⚠️ **顺一遍把小东当「人」称呼的文案**（「他」「小东说」之类）。改名后叙述主体从
  一个人变成店，读起来不能像店铺在自称第三人称。
- 已核实：`小东` **只在农场仓库里出现**，主站 `frontend-web` 与 `stockwise_final`
  均为 0 处，不牵连别的仓库。

## 七、状态与存档

```js
d.storeDemand = {
  day: '2026-08-22',
  staples:  [{ cropId, need, filled }],                    // ① 每日基础补货
  board:    [{ id, kind, items:[{cropId,qty}], coins, xp, ep,
               postedAt, expiresAt, accepted }],           // ② / ③
  forecast: [{ date, cropIds, reason: 'sale'|'season' }],  // 预告
  nextPostAt, lastSyncAt, source: 'live'|'local'
}
```

🔒 **新增嵌套字段必须在 `state.js` 的 `init()` 里显式 deep-fill** ——
`Object.assign` 只补顶层，`plots[]` 更是完全不合并（项目 memory 已记 5 条同类坑）。

🔒 时刻一律用**绝对时间戳**（同 `stall.js`），离线也自然到点。

🔒 **离线回来只补当前该有的板面，不追发历史订单**。离线 3 天时 `nextPostAt` 已过去
十几个周期，按周期数补发会一次性砸出几十张单 —— 那既荒唐又等于变相无限收购。
正确行为：过期的清掉，按「现在」重新铺满板面。

🔒 **日期一律走 `Farm.state.getDateString()`**（与签到、每日任务同源），
不要自己 `new Date()` 算日界 —— 萨省 UTC-6，自己算必错一天（项目铁律）。

🔒 **订单生成即落档，刷新不重 roll**。生成后写进存档再展示；否则玩家可以靠
刷新页面反复摇订单（save-scum），接单上限就白设了。

### 七之二、老玩家的存量库存（上线当天就会撞上）

老玩家的谷仓里躺着一堆按「随时能大宗卖」的预期攒下来的菜。收购一关，这批货可能
既不在补货单里、也不在订单里 —— 一上线就是「我的东西卖不掉了」。

处理：**首次进入新版本时发一张一次性的「开业清仓单」**，按旧的大宗价把当前库存
一次收掉（玩家可以不交，留着等溢价更高的订单）。只发一次，记 `d.storeDemand.clearedLegacy = true`。

## 八、不做（YAGNI）

- 不做订单议价 / 拒单惩罚 / 声望等级。
- 不做「限时冲刺」类倒计时压力玩法。
- 不做玩家之间的订单转让。
- **不加推送通知**。「有提醒」只做游戏内红点（复用东超头像上已有的 badge）——
  974 个会员里 `push.optIn` 只有 1 人，为它做推送是白做（见项目 memory 的 08-11 审计）。
- 一期不碰菜摊、厨房、偷菜、积分商店的任何数值。

## 九、验收

功能：
1. 谷仓再也卖不了菜；三层需求都能出单、能交付、能到账。
2. 接单上限生效：超过 3 单时第 4 单只能看不能接；没接的单点交付无效；
   放弃已接的单可立刻腾出位置且无惩罚；每日基础补货不占位。
3. 订单过期后消失，且**金币 / 声望 / 后续出单节奏均无变化**。
4. 预告板显示未来 3–7 天，且与随后真实出单一致。
5. 「东超」在 UI 上全量替换，找不到「小东」。

回归（进部署闸门）：
- **经济模拟**：新模式日收入 ≥ 旧模式（多组地块数 × 登录频次）。
- **不卡死**：模拟连续 7 天只种「当前无人订购」的菜，玩家仍有正收入路径（菜摊 + 基础补货 + 厨房）。
- **离线不惩罚**：离线 3 天后回来，无扣款、无掉级、订单正常刷新。
- **后端挂掉仍有订单**：`farm-demand` 返回 500 / 超时 → 本地随机照常出单。
- **`totalDeliveries` 接管**：订单交付后计数自增，`life-story` 的 `deliver_first` 能触发。
- **存档迁移**：老存档（无 `storeDemand`）打开不报错、字段被补全。
- **离线不追发**：把 `nextPostAt` 手动调到 3 天前，回来后板面是正常张数，不是几十张。
- **刷新不重 roll**：同一时刻反复重载，板上订单 id 不变。
- **存量库存有出路**：老存档满仓进新版，能拿到一次性开业清仓单。

## 十、分期

- **一期（纯游戏内，零后端依赖）**：三层需求 + 接单容量 + 预告板（先用应季表推）+
  关大宗 + `totalDeliveries` 接管 + 来单红点提醒 + 小东→东超改名。
- **二期（真店挂钩）**：StockWise `GET /api/public/farm-demand` + 权重 ×3 + 特价标记。

二期跨仓库（StockWise 走 GitHub Actions 部署），与一期解耦：一期不依赖它也完整可玩。

## 附：与现有约定的关系

- 沿用 `orders.js` 的货币纪律：农场币是主奖励且充裕，**超市积分保持稀缺**且有每日硬上限。
- 沿用 cozy 原则：无惩罚性倒计时、无失败态。
- 社交奖励仍**只发农场币不发超市积分**（偷菜红线）。

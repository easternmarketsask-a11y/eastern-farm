# Localization (i18n) Guidelines

Eastern Farm ships with **中文 (Simplified Chinese)** and **English** in V1.
Both languages are first-class — neither is "primary translation, other is
second." The mom may use Chinese, the kid may use English, and they may
toggle mid-session.

---

## Implementation

All static UI strings live in `data/i18n.json` under the `strings` key:

```json
{
  "btn_plant": { "zh": "种植", "en": "Plant" }
}
```

Access via:

```js
Farm.i18n.t('btn_plant');           // → "种植" or "Plant"
Farm.i18n.t('toast_planted', { crop: '番茄' });  // template vars
```

DOM elements with `data-i18n="key"` are auto-translated by
`Farm.i18n.applyAll()` (called on language change).

Dynamic content (crop names, story text) uses `name_zh` / `name_en` /
`story_zh` / `story_en` fields directly from `data/crops.json`, picked by
`Farm.state.data.language`.

## Style Guide

### Chinese (zh)
- Use **Simplified Chinese (简体中文)** in V1. Traditional (繁體中文) is V2
  consideration.
- Tone: warm, conversational, informal. The storekeeper is friendly, not
  formal. Use 你 not 您 (less stiff for parent-child play).
- Punctuation: use Chinese punctuation marks (，。！？) NOT half-width
  ones (,.!?). Exception: in code identifiers stay English.
- No emoji-heavy: too many emoji feel cheap. Strategic placement only.
- Slang OK in storekeeper lines ("超划算", "捎个问候"), formal in system
  messages ("已使用", "等级提升").

### English (en)
- Tone: warm, casual North American English. Not formal British, not
  hyper-cute "OMG".
- "East Points" is the official name (not "Eastern Points" or "E-Points").
- "Eastern Market" is always written fully — never "EM" in user-facing text.
- Crop English names: prefer culturally precise ("Asian eggplant" not
  "eggplant"; "Chinese chive" not "chive" alone). See `docs/CROPS.md`.

## Tricky Translation Cases

### 节日 (Festival names)
- 春节 → "Spring Festival" (NOT "Chinese New Year" — that's the
  Western-centric framing; the festival is a Lunar New Year)
- 中秋节 → "Mid-Autumn Festival" (NOT "Moon Cake Festival")
- 端午节 → "Dragon Boat Festival" (universally translated this way)
- 清明节 → "Qingming Festival" (Pinyin; "Tomb-Sweeping Day" is acceptable
  but less elegant)

### Cultural concepts
- 福 (good fortune) → just say "good fortune", don't try "blessing" (religious)
- 团圆 (family reunion) → "family reunion", straightforward
- 桔/吉 wordplay → explain it inline: "kumquat (sounds like 'lucky')"

### Game mechanics
- "East Points" not "Eastern Points" (snappier)
- "Coupon code" not "voucher" or "discount code" (matches store usage)
- "Harvest" not "Reap" or "Collect" (most natural)
- "Plot" not "Tile" or "Square" (farms have plots)

## Adding a New String

1. Add a new key to `data/i18n.json`:
   ```json
   "new_feature_title": { "zh": "新功能", "en": "New Feature" }
   ```

2. Reference in HTML:
   ```html
   <div data-i18n="new_feature_title"></div>
   ```

3. Or in JS:
   ```js
   element.textContent = Farm.i18n.t('new_feature_title');
   ```

4. For variables:
   ```json
   "welcome_user": { "zh": "你好，{name}", "en": "Hello, {name}" }
   ```
   ```js
   Farm.i18n.t('welcome_user', { name: 'Chris' });
   ```

## Language Toggle

The toggle lives in Settings (⚙️ Settings → Language). Toggle:

1. Updates `Farm.state.data.language`
2. Saves immediately to localStorage
3. Calls `Farm.i18n.setLanguage(lang)` which calls `applyAll()`
4. Re-renders farm grid (for crop name labels)
5. Refreshes storekeeper greeting

**Important**: language is per-device, not per-account. A family
sharing a device may want different settings. V2 could add a "language
this session" override.

## Future Languages (V2+)

Possible additions and the considerations:

| Language | Why | Effort |
|---|---|---|
| 繁體中文 | Hong Kong/Taiwan customers in Saskatoon | Low — clone zh strings, manual character conversion |
| Vietnamese | Significant Vietnamese-Canadian community | Medium — need native translator |
| Korean | Smaller Korean community in Saskatoon | Medium |
| French | Canadian official language | Low to add UI; festival names need care |

The infrastructure (string lookup with language code) supports it natively.
Just expand `data/i18n.json` and update crop JSON.

## Testing

For every UI change:
1. Toggle to 中文 — verify everything renders correctly
2. Toggle to English — verify everything renders correctly
3. Check that text doesn't overflow buttons (Chinese is often shorter,
   English longer; design for the longer case)
4. Verify mixed-content cases: e.g., a toast with both a translated
   string AND a crop name uses the right language for both
